Attention mechanism

Dense FFN & LatentMoE

The first feed-forward layer in each pair is a small dense FFN; the second is a sparse LatentMoE that compresses to a shared latent before all-to-all dispatch, routes each token to 8 of 512 experts, then projects back. Both use SwiGLU.

Load balancing
  • Global-batch load-balancing loss — empirical expert frequencies aggregated across data-parallel workers and micro-batches.
  • GShard-style loss performed similarly to the loss-free variant once global aggregation was ensured.
  • Final implementation converged to fully dropless MoE with variable-size all-to-all and bounded memory under high imbalance.
Why no shared experts

Adding shared experts to this interleaved layout had little or no benefit, so the final design omits them. The router decision uses the original representation (not the compressed latent); only the dispatched payload is compressed to dim 3072, reducing all-to-all communication volume.

Scaling rule
  • Family specified primarily by layer count L.
  • Hidden size D = L × 256 / 3 per the report's printed relation.
  • Query heads set to L, rounded up to the nearest multiple of 16 (tensor-parallel serving).
  • Dense FFN expands hidden by 2×.
  • LatentMoE uses 2× compression and 3× expansion inside each expert.
  • Sparsity fixed at top-8 / 512 to balance quality with training & inference efficiency.
The D = L×256/3 relation is read from the report's prose; PDF math rendering may be ambiguous, so it is reported but not over-emphasized.

Mixture selection methodology
  • ~40 internal NLL benchmarks grouped into Coding, STEM, Math, General Knowledge, Multilingual.
  • Aggregate target = 0.5 Coding + 0.175 STEM + 0.175 Math + 0.1 General + 0.05 Multilingual.
  • Thousands of small models (760M–4B active) trained to search mixtures.
  • Example frontier: 183 models from scratch, equal TPP, 3 scales, 61 mixtures.
  • Max dataset repetition cap of 8.
Data governance
  • Proprietary crawler respects robots.txt and related meta/HTML controls.
  • Excludes USTR Notorious Markets sources and policy-violating sources.
  • Third-party data governed by commercial agreements.
  • No private customer data or Microsoft product/service data except explicit opt-in or applicable agreements respecting opt-outs.
  • PII-risk & safety filtering before training.
  • Full provider list not disclosed for privacy / legal / safety / competitive reasons.

Attention zero-initialization

Attention output is initialized to zero by setting the output RMSNorm gains to zero. The initial model therefore behaves like a stack of token-wise feed-forward layers; cross-token interactions gradually kick in during training.

Motivation: random attention initially acts like causal mean-pooling, which reduces token diversity and can imbalance MoE routing.

Mid-training & long-context extension

Mid-training draws entirely from the pretraining corpus — no new or synthetic sources — but re-weights the mixture toward STEM, math and code, and repacks data at longer sequence lengths to extend context with minimal distribution shift.

GRPO-style objective

For prompt q, the rollout policy samples a group of G responses y₁:G; each gets a scalar reward Rᵢ = R(q, yᵢ). A token-level policy-gradient objective is derived from GRPO.

Ai = ( Ri − mean(R1:G) ) / std(R1:G)
ri,t = πθ(token) / πold(token)
Two modifications
  • Adaptive entropy control — dynamically adjusts upper clip bound k to target policy entropy H*.
  • Outer ratio clip — hard-clips all branches with rmax to avoid catastrophic gradient-norm spikes.
Reward decomposition
R(q,yi) = Rtask + wlang·Rlang − wlen·Rlen
  • Language consistency reward penalizes non-English words in the CoT.
  • Length penalty depends on response length and the problem's pass rate.
Sampling
  • Early-exit problem sampling with G_early < G; final group pass-rate filter.
  • Top-p sampling p = 0.97 with top-p truncation mask replay to reduce off-policy mismatch.

Helpfulness & Safety climb

Optimizes general helpfulness judged by human/AI feedback together with safety compliance — using a reward model based on a post-trained MAI-Base-1, plus a style guide and target-behavior descriptions.

Both unsafe compliance and unnecessary refusal are treated as defects within the same reward construction — safety and helpfulness are optimized jointly, not as a bolt-on filter.

▸Self-distillation (Trace Distillation SFT)

Checkpoint rescue

Recover and stabilize a struggling climb from successful traces.

Format migration

Move behavior onto a new output / interaction format.

Base-policy upgrade

Re-seed RL from a stronger consolidated base policy.

Findings
  • O(1M) reasoning traces suffice to match teacher performance while retaining SFT stability.
  • Successful traces only in the final approach.
  • Later-stage traces matter; early traces degrade performance — even final-checkpoint traces are weaker than diverse strong-checkpoint traces.
  • Prompt diversity beats more traces per prompt at a fixed token budget.
  • Mix mid-training data with reasoning traces to avoid forgetting long-context behavior.

Rocket RL infrastructure

Rocket is the asynchronous RL system that pairs the YOLO learner with an SGLang inference engine. Rollout workers generate long trajectories while training workers update the policy; a transfer plan reshards weights between the two sides.

YOLO learner
training workers
  • Policy-gradient updates (GRPO)
  • Dropless MoE training
  • BF16 learner
weight transfer ↓reshard learner → inference shards
rollouts ↑trajectories + rewards
SGLang inference engine
rollout workers · thousands of inference GPUs
  • Long-rollout generation
  • BF16 inference engine
  • MoE routing replay · top-p mask replay
Key mechanisms
  • BF16 on both sides — learner and inference engine use BF16 to reduce numerical mismatch.
  • MoE routing replay and top-p mask replay keep rollouts on-policy.
  • Transfer plan handles resharding between learner and inference shards.
  • Example: a 36-server fleet split into four groups of 9-server transfers.
Why it matters
  • Thousands of inference GPUs and long rollouts demand careful scheduling.
  • Stale-policy control bounds how far rollouts drift from the learner.
  • KV-cache memory is the dominant bottleneck.
  • Lower-precision alternatives increased numerics gaps; BF16 stabilized RL.
